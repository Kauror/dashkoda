{% comment %} Several dated series on one pair of axes, drawn on the server. Context: chart – a TrendChart from `apps/dashboard/sparkline.py` Why not `chart_figure`: ECharts is a large bundle and the overview is the page every viewer loads first. Two lines of a dozen points each do not justify shipping a charting library, so the coordinates are computed in `apps/dashboard/sparkline.py` and emitted as plain `` elements. Geometry travels in the `points` attribute and the dash pattern in `stroke-dasharray`, never in a `style`. That is what keeps `style-src 'self'` intact. The two lines differ in **pattern as well as colour** — one solid, one dashed — so they stay distinguishable in greyscale and to a reader who cannot separate the two hues. The stroke classes are spelled out per branch rather than built from `line.style`, because Tailwind generates utilities by scanning this file and a class assembled at render time would simply not exist. The axis labels are HTML rather than SVG text: the drawing is stretched to the card's width with `preserveAspectRatio="none"`, which would stretch any glyph inside it. They are hidden on a narrow screen, where twelve month names would either overflow the card or truncate to nothing legible; the range below and the table beneath state the same window in words. The same contract as `chart_figure` applies to the alternative: the table is **not** a fallback for a broken drawing — it stays in the document for every reader, one table per line, each naming its own source. The two are never merged into one table on a shared date column, because they are two sources that report on their own days and a blank cell would read as a missing measurement. Hovering a month shows what was read that month, and does it with no JavaScript required. Three attribute-only decisions carry that: - the hit target is a full-height strip per observation date, painted **first** so its hover fill sits behind the lines rather than over them. Everything drawn after it carries `pointer-events="none"`, so the strip is what a pointer meets anywhere in its column — a reader aims at a month, not at a dot; - the reading is an SVG ``, which the browser shows as its own tooltip. No script, no positioned element, no stylesheet rule; - a dot is a **zero-length path with a round linecap**, which SVG defines as drawing a circle of the stroke width. A `<circle>` would be squashed into an ellipse by `preserveAspectRatio="none"`; a stroke marked `vector-effect="non-scaling-stroke"` is measured in screen pixels and stays round at any card width. The native `<title>` tooltip is the floor, not the experience: browsers show it only after their own delay, only while the pointer holds perfectly still, and never on touch. `data-trend-chart` is where `frontend/src/trend-tooltip.js` picks the figure up and replaces that with an instant styled readout that also answers a tap — lifting each `<title>` out of the live document so the two tooltips cannot stack. With the bundle blocked the `<title>`s simply stay, and this figure is exactly what it always was. The figure is `relative` because the script positions the readout inside it. Neither tooltip reaches a keyboard.
